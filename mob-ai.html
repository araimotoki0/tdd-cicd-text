AIを活用したグループ作業

人と AI が、共通の目標に向かって「考える → 作る → 見る → 判断する → 学ぶ」

AIで開発が10倍速くなったら？

AI によって、コードを書く・テストする・修正するといった作業は急速に速くなっています。
では、開発が10倍速くなったら、価値を生み出すスピードも10倍になるのでしょうか？

Speed of making

「作る速さ」

Speed of creating value

「価値を生み出す速さ」

この2つは、同じではありません。

AIの時代、チームの価値は？

AIは、チームの働き方を変え始めている

以前は複数人で分担していた仕事（実装・テスト・レビュー）を、今は1人の開発者が AI エージェントを使って進められます。 チームの中で人が担う役割も、大きく変わり始めています。

それでも、チームにはどんな価値がある？

1人と AI だけでは、見落としや思い込みに気づきにくくなります。 異なる知識や視点を持ち寄り、AI の成果を一緒に確かめて判断できることが、チームの価値です。

テスラに学ぶフィードバックループ

大事なのは、作る速さそのものではなく、チームがどれだけ速く学び、次の改善につなげられるかです。

走行データ→ 学ぶ→ 改善する→ 現実の世界へ→ また学ぶ

AIが書いたコードは、そのまま使える？

AI は短い時間でコードを作れます。でも「動く」ことと「安心して使える」ことは別です。
重要なのは、AI の回答を信じることではなく、テストや分析で確かめることです。

実際のAI開発を見てみよう

講師のデモで、上の4つのステップを1周します（約10分）

題材：スプリントで使う「KPT 振り返りボード」（HTML / CSS / JavaScript だけ・テストは node --test）

1

基準を決める（人間）

AI に「何を作るか」だけでなく、「何を満たすべきか」を先に渡します。仕様は AGENTS.md、基準はテストです。

AGENTS.md（抜粋）

## 満たす条件（基準）
- tests/kpt.test.js のテストがすべて通ること（npm test）
- カードの本文は前後の空白を取り除き、1〜140文字。空や長すぎる場合はエラー
- 種類は keep / problem / try のどれか

tests/kpt.test.js（7件のうち2件）

test('本文の前後の空白は取り除く', () => {
  assert.equal(createCard('  レビューが遅い  ', 'problem').text, 'レビューが遅い');
});

test('140文字を超える本文はエラー', () => {
  assert.throws(() => createCard('あ'.repeat(141), 'keep'));
  assert.doesNotThrow(() => createCard('あ'.repeat(140), 'keep'));
});

生成する（AI）

AI に作らせます。テストは7件すべて通り、ブラウザでも動きます。

tests/kpt.test.js がすべて通るようにして、最後に npm test を実行してください。

3

検証する（3つの AI エージェントが同時に）

観点ごとにレビュー担当のエージェントを用意しておき、同時にレビューさせます。レビュー担当にはコードを書き換えさせません。

.claude/agents/security-reviewer.md（効率・品質の担当も同じ形で用意）

---
name: security-reviewer
description: セキュリティ担当。コードに脆弱性がないかをレビューする。コードは書き換えない。
tools: Read, Grep, Glob
---
あなたはセキュリティ担当のレビュアーです。
見る観点: XSS / 保存データの読み込み / 入力値の検証が画面側だけになっていないか

AI への指示

security-reviewer、efficiency-reviewer、quality-reviewer の3つのサブエージェントを
並行して動かして、このコードをレビューしてください。
結果は観点ごとに、重要なもの3件までの表にしてください。

テストは通っていたのに、セキュリティ担当がこの行を指摘します。本文をそのまま HTML として表示しています。

src/app.js（AI が書いたコード）

html += `<div class="card">${card.text}</div>`;

カードの本文に次を入れると、他の人の画面でプログラムが動いてしまいます（XSS）。

カードに入力する文字

<img src=x onerror="alert('XSS')">
観点一番重要な指摘
🛡️ セキュリティ本文を innerHTML でそのまま表示している（XSS）
⚡ 効率1文字入力するたびに、保存とボード全体の描き直しをしている
✅ 品質空白だけ（" "）のカードが作れてしまう。テストにこのケースがない
4

改善する（どれを直すかは人間が判断）

全部を AI の言うとおりに直すのではなく、人間が選びます。今回は効率の指摘を「カードが少ないので見送り」と判断しました。

AI への指示

次の2つを直してください。効率の指摘は、今回はカードが少ないので見送ります。
1. セキュリティ：XSS（本文を textContent で表示する）
2. 品質：空白だけのカードを作れないようにする。
   先にテストを足して失敗することを確認してから（Red）、直してください（Green）。

src/app.js（直したあとの例）

const div = document.createElement('div');
div.className = 'card';
div.textContent = card.text;   // 文字として表示するので、タグは動かない
column.appendChild(div);

tests/kpt.test.js（足したテスト：最初は失敗 → 直して成功）

test('空白だけの本文はエラー', () => {
  assert.throws(() => createCard('   ', 'keep'));
});

MobAIとは？

Joe Justice は2023年から、AI を活用したグループ作業「MobAI」を提唱してきました。 大切にしているのは、AI に作業を任せることだけではなく、人と AI が互いの強みを活かし、より良い成果を生み出すことです。

考える→ 作る→ 見る→ 判断する→ 学ぶ

目的

お題

  • • AI の提案をそのまま採用せず、みんなのアイデアを加えながら、さらに面白いものへ進化させてみましょう

AI の画面を共有し、みんなで会話しながら1つの作品を作ってみましょう。 役割分担や交代の仕方も自由です。

現場でMobAIをどう活かす？

⏱ 13分

開発現場での AI 活用や共同作業の現状を共有し、人間と AI エージェントが協働する可能性を考えます。

① 現場の今を共有する

  • • 現在、どのような AI ツールを使っていますか？
  • • AI を使った開発は、個人作業が中心ですか？ それともチームで共同作業していますか？
  • • AI エージェントを活用した開発は、どこまで進んでいますか？

② これからの共同作業を考える

AI エージェントが開発に参加するなら、チームの働き方をどう変えたいですか？

  • • 共同作業：1人で AI を使う作業と、複数人で AI を使う作業をどう使い分ける？
  • • 役割分担：人間と AI エージェントに、どんな役割を任せる？
  • • 品質：AI が作った成果物を、どのように検証する？
  • • 学習：AI の使い方や開発で得た知識を、どうチームで共有する？

なぜモブAIをするのか？

AI がコードの生成・テスト・レビューを担えるようになり、1人の開発者ができることは大きく広がっています。 しかし開発で重要なのは、コードを書くことだけではありません。 何を作るべきか、どのような品質を求めるか、どう改善するかを考える必要があります。

AI が生成したコードにも、機能の正しさに加えて、セキュリティ・処理速度・保守性などを検証し、改善を重ねる必要があります。 これからの開発者には、AI を使いこなすだけでなく、問題を理解し、品質を見極め、異なる知識や視点を活かす力が求められます。

チームの価値は、単に作業を分担することではありません。 異なる知識や視点を持ち寄り、互いの考えを検証し、結果から一緒に学ぶことで、1人では生み出せない成果につなげることです。

人間と AI が、それぞれの強みを活かして協働すること。 MobAI は、そうした協働を通じて、検証と学習を繰り返しながら、より良い成果を生み出すための方法の1つです。
