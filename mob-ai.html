🎬 解説動画「MobAI ってなに？」（約3分・音声あり）

① AI の道具は、1人では追いきれない

エージェント、スキル、フック、MCP、権限、ワークフロー……。18か月前にはなかった新しい仕組みが、15個以上。1人で全部を使いこなすのは大変でも、支え合う3人のチームなら、ずっと簡単です。

② 人か AI かは、もう重要ではない

MobAI は「AI を活用したグループ作業」。メンバーが人間か、AI か、その両方かは重要ではありません。人と AI が同じ目標に向かって、考える → 作る → 見る → 判断する → 学ぶ、をくり返します。

③ 速さ・質・学び

その場で決めるので待ちや引き継ぎがない（速さ）。AI の成果物を複数の目で確かめる（質）。学んだことや AI に渡す文脈を、AGENTS.md やスキルのファイルとしてチームに残す（学び）。

④ 役割を決めることが、目的ではない

テスラでは決まった役割は使っていませんでした。役割はグループ作業を始めるための入り口。本当に大事なのは、同じ画面を見て、一緒に考え、一緒に決めることです。

最高の品質を、速く、効率よく。

AI の世界は、1人では追いきれないほど広く、速く変わります。だから、人と AI がグループになって、一緒に作り、複数の目で確かめ、学んだことをチームに残す。それが MobAI です。

AIで開発が10倍速くなったら？

AI によって、コードを書く・テストする・修正するといった作業は急速に速くなっています。
では、開発が10倍速くなったら、価値を生み出すスピードも10倍になるのでしょうか？

AIの時代、チームの価値は？

AIは、チームの働き方を変え始めている

以前は複数人で分担していた仕事（実装・テスト・レビュー）を、今は1人の開発者が AI エージェントを使って進められます。 チームの中で人が担う役割も、大きく変わり始めています。

それでも、チームにはどんな価値がある？

1人と AI だけでは、見落としや思い込みに気づきにくくなります。 異なる知識や視点を持ち寄り、AI の成果を一緒に確かめて判断できることが、チームの価値です。

テスラに学ぶフィードバックループ

大事なのは、作る速さそのものではなく、チームがどれだけ速く学び、次の改善につなげられるかです。

走行データ→ 学ぶ→ 改善する→ 現実の世界へ→ また学ぶ

AIが書いたコードは、そのまま使える？

AI は短い時間でコードを作れます。でも「動く」ことと「安心して使える」ことは別です。
重要なのは、AI の回答を信じることではなく、テストや分析で確かめることです。

docs/spec.md

# 仕様：KPT 振り返りボード

## 目的
スプリントの振り返りで、チーム全員が Keep / Problem / Try を書き出して共有できるようにする。

## ユーザーストーリー
- 開発者として、振り返りで気づいたことをカードにして追加したい。思いついたその場で書き留めるため。
- スクラムマスターとして、Keep / Problem / Try ごとの枚数を見たい。どこに話し合いの時間を使うか決めるため。

## 機能
1. 種類（Keep / Problem / Try）を選んで、ひとことのカードを追加できる
2. カードは種類ごとの列に表示される
3. 各列に、その種類のカードの枚数を表示する
4. カードはブラウザに保存され、再読み込みしても残る

## 受け入れ条件
- カードの本文は、前後の空白を取り除いたうえで 1〜140 文字
- 本文が空、または 140 文字を超える場合は、エラーメッセージを表示して追加しない
- 種類は keep / problem / try のどれか
- 入力された本文は、そのまま文字として表示される（HTML として解釈されない）

## 対象外（今回は作らない）
- カードの編集・削除
- 複数人でのリアルタイム共有

基準：受け入れ条件を、確かめられる形（テスト）にしたもの

tests/kpt.test.js

// 受け入れ条件（docs/spec.md）を確かめるテスト
import { test } from 'node:test';
import assert from 'node:assert/strict';
import { createCard, addCard, countByType } from '../src/kpt.js';

test('カードを作れる', () => {
  const card = createCard('ペアプロがうまくいった', 'keep');
  assert.equal(card.text, 'ペアプロがうまくいった');
  assert.equal(card.type, 'keep');
  assert.ok(card.id);
});

test('本文の前後の空白は取り除く', () => {
  assert.equal(createCard('  レビューが遅い  ', 'problem').text, 'レビューが遅い');
});

test('空の本文はエラー', () => {
  assert.throws(() => createCard('', 'keep'));
});

test('140文字を超える本文はエラー', () => {
  assert.throws(() => createCard('あ'.repeat(141), 'keep'));
  assert.doesNotThrow(() => createCard('あ'.repeat(140), 'keep'));
});

test('種類は keep / problem / try だけ', () => {
  assert.throws(() => createCard('なにか', 'other'));
});

test('追加しても元のリストは変えない', () => {
  const list = [];
  const next = addCard(list, createCard('朝会を短く', 'try'));
  assert.equal(list.length, 0);
  assert.equal(next.length, 1);
});

test('種類ごとの数を数えられる', () => {
  let list = [];
  list = addCard(list, createCard('a', 'keep'));
  list = addCard(list, createCard('b', 'keep'));
  list = addCard(list, createCard('c', 'try'));
  assert.deepEqual(countByType(list), { keep: 2, problem: 0, try: 1 });
});

src/kpt.js

// KPT ボードのロジック（DOM を使わない）
export const TYPES = ['keep', 'problem', 'try'];

export function createCard(text, type) {
  if (text.length === 0) {
    throw new Error('本文を入力してください');
  }
  if (text.length > 140) {
    throw new Error('本文は140文字以内にしてください');
  }
  if (!TYPES.includes(type)) {
    throw new Error('種類が正しくありません');
  }
  return { id: Date.now(), text: text.trim(), type };
}

export function addCard(list, card) {
  return [...list, card];
}

export function countByType(list) {
  const result = {};
  for (const type of TYPES) {
    result[type] = list.filter((card) => card.type === type).length;
  }
  return result;
}

src/app.js

// KPT ボードの画面処理
import { TYPES, createCard, addCard, countByType } from './kpt.js';

const LABELS = { keep: 'Keep', problem: 'Problem', try: 'Try' };

const form = document.getElementById('cardForm');
const textInput = document.getElementById('cardText');
const typeSelect = document.getElementById('cardType');
const error = document.getElementById('error');
const board = document.getElementById('board');

let cards = JSON.parse(localStorage.getItem('kpt-cards')) || [];
textInput.value = localStorage.getItem('kpt-draft') || '';

function save() {
  localStorage.setItem('kpt-cards', JSON.stringify(cards));
}

function render() {
  board.innerHTML = '';
  for (const type of TYPES) {
    const counts = countByType(cards);
    let html = `<section class="column ${type}"><h2>${LABELS[type]} <span class="count">${counts[type]}</span></h2>`;
    for (const card of cards.filter((c) => c.type === type)) {
      html += `<div class="card">${card.text}</div>`;
    }
    html += '</section>';
    board.innerHTML += html;
  }
}

// 入力途中の内容も残しておく
textInput.addEventListener('input', () => {
  localStorage.setItem('kpt-draft', textInput.value);
  render();
});

form.addEventListener('submit', (event) => {
  event.preventDefault();
  try {
    cards = addCard(cards, createCard(textInput.value, typeSelect.value));
    save();
    textInput.value = '';
    localStorage.removeItem('kpt-draft');
    error.textContent = '';
    render();
  } catch (e) {
    error.textContent = e.message;
  }
});

render();

# セキュリティレビュー

`src/` と `index.html` を読み、脆弱性を探します。**コードは書き換えません。**

src/kpt.js（直したあと）

// KPT ボードのロジック（DOM を使わない）
export const TYPES = ['keep', 'problem', 'try'];

export function createCard(text, type) {
  // 先に前後の空白を取り除いてから、文字数を確かめる
  const trimmed = text.trim();
  if (trimmed.length === 0) {
    throw new Error('本文を入力してください');
  }
  if (trimmed.length > 140) {
    throw new Error('本文は140文字以内にしてください');
  }
  if (!TYPES.includes(type)) {
    throw new Error('種類が正しくありません');
  }
  return { id: Date.now(), text: trimmed, type };
}

export function addCard(list, card) {
  return [...list, card];
}

export function countByType(list) {
  const result = {};
  for (const type of TYPES) {
    result[type] = list.filter((card) => card.type === type).length;
  }
  return result;
}

src/app.js（直したあと）

// KPT ボードの画面処理
import { TYPES, createCard, addCard, countByType } from './kpt.js';

const LABELS = { keep: 'Keep', problem: 'Problem', try: 'Try' };

const form = document.getElementById('cardForm');
const textInput = document.getElementById('cardText');
const typeSelect = document.getElementById('cardType');
const error = document.getElementById('error');
const board = document.getElementById('board');

let cards = JSON.parse(localStorage.getItem('kpt-cards')) || [];
textInput.value = localStorage.getItem('kpt-draft') || '';

function save() {
  localStorage.setItem('kpt-cards', JSON.stringify(cards));
}

function render() {
  board.replaceChildren();
  for (const type of TYPES) {
    const counts = countByType(cards);

    const column = document.createElement('section');
    column.className = `column ${type}`;

    const heading = document.createElement('h2');
    heading.textContent = `${LABELS[type]} `;
    const count = document.createElement('span');
    count.className = 'count';
    count.textContent = counts[type];
    heading.appendChild(count);
    column.appendChild(heading);

    for (const card of cards.filter((c) => c.type === type)) {
      const div = document.createElement('div');
      div.className = 'card';
      div.textContent = card.text; // 文字として表示するので、タグは動かない
      column.appendChild(div);
    }
    board.appendChild(column);
  }
}

// 入力途中の内容も残しておく（効率の指摘は今回は見送り）
textInput.addEventListener('input', () => {
  localStorage.setItem('kpt-draft', textInput.value);
  render();
});

form.addEventListener('submit', (event) => {
  event.preventDefault();
  try {
    cards = addCard(cards, createCard(textInput.value, typeSelect.value));
    save();
    textInput.value = '';
    localStorage.removeItem('kpt-draft');
    error.textContent = '';
    render();
  } catch (e) {
    error.textContent = e.message;
  }
});

render();

  • • 品質：AI が作った成果物を、どのように検証する？
  • • 学習：AI の使い方や開発で得た知識を、どうチームで共有する？

なぜモブAIをするのか？

AI がコードの生成・テスト・レビューを担えるようになり、1人の開発者ができることは大きく広がっています。 しかし開発で重要なのは、コードを書くことだけではありません。 何を作るべきか、どのような品質を求めるか、どう改善するかを考える必要があります。

AI が生成したコードにも、機能の正しさに加えて、セキュリティ・処理速度・保守性などを検証し、改善を重ねる必要があります。 これからの開発者には、AI を使いこなすだけでなく、問題を理解し、品質を見極め、異なる知識や視点を活かす力が求められます。

チームの価値は、単に作業を分担することではありません。 異なる知識や視点を持ち寄り、互いの考えを検証し、結果から一緒に学ぶことで、1人では生み出せない成果につなげることです。

人間と AI が、それぞれの強みを活かして協働すること。 MobAI は、そうした協働を通じて、検証と学習を繰り返しながら、より良い成果を生み出すための方法の1つです。
