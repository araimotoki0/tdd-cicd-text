① AI の道具は、1人では追いきれない

エージェント、スキル、フック、MCP、権限、ワークフロー……。18か月前にはなかった新しい仕組みが、15個以上。1人で全部を使いこなすのは大変でも、支え合う3人のチームなら、ずっと簡単です。

② 人か AI かは、もう重要ではない

MobAI は「AI を活用したグループ作業」。メンバーが人間か、AI か、その両方かは重要ではありません。人と AI が同じ目標に向かって、考える → 作る → 見る → 判断する → 学ぶ、をくり返します。

③ 速さ・質・学び

その場で決めるので待ちや引き継ぎがない（速さ）。AI の成果物を複数の目で確かめる（質）。学んだことや AI に渡す文脈を、AGENTS.md やスキルのファイルとしてチームに残す（学び）。

④ 役割を決めることが、目的ではない

テスラでは決まった役割は使っていませんでした。役割はグループ作業を始めるための入り口。本当に大事なのは、同じ画面を見て、一緒に考え、一緒に決めることです。

最高の品質を、速く、効率よく。

AI の世界は、1人では追いきれないほど広く、速く変わります。だから、人と AI がグループになって、一緒に作り、複数の目で確かめ、学んだことをチームに残す。それが MobAI です。

AIは、チームの働き方を変え始めている

AI の進化によって、チームの働き方も大きく変わり始めています。 これまでは、開発・コードレビュー・テストなどを複数人で分担することが一般的でした。 しかし今では、1人の開発者が複数の AI エージェントを活用し、コードの生成からレビュー、テストまでを並行して進めることも可能になっています。

もちろん、企業によってはセキュリティや既存システム、組織の制約もあり、すぐにこうした開発方法を取り入れられるとは限りません。 それでも、これまで人間が分担していた作業の一部を、AI が担えるようになってきたことは大きな変化です。

AI によって、1人の開発者でもコードの生成・レビュー・テストなど、多くの作業を進められるようになりました。 では、これからは人間のチームが必要なくなるのでしょうか？

実際のプロダクト開発には、技術だけでなく、顧客のニーズ、ビジネスの目標、品質、運用など、さまざまな知識や視点が関わります。 AI は幅広い分野の作業や判断を支援できますが、1人で必要な情報をすべて把握し、適切に判断できるとは限りません。

一方で、複数人で開発すれば、必ず良い成果が生まれるわけでもありません。 認識の違いや、意思決定の遅れが問題になることもあります。

チームの価値は、単に作業を分担することではありません。 異なる知識や視点を組み合わせ、より良い判断をし、その結果から一緒に学べることです。

なぜモブAIをするのか？

AI がコードの生成・テスト・レビューを担えるようになり、1人の開発者ができることは大きく広がっています。 しかし開発で重要なのは、コードを書くことだけではありません。 何を作るべきか、どのような品質を求めるか、どう改善するかを考える必要があります。

AI が生成したコードにも、機能の正しさに加えて、セキュリティ・処理速度・保守性などを検証し、改善を重ねる必要があります。 これからの開発者には、AI を使いこなすだけでなく、問題を理解し、品質を見極め、異なる知識や視点を活かす力が求められます。

チームの価値は、単に作業を分担することではありません。 異なる知識や視点を持ち寄り、互いの考えを検証し、結果から一緒に学ぶことで、1人では生み出せない成果につなげることです。

人間と AI が、それぞれの強みを活かして協働すること。 MobAI は、そうした協働を通じて、検証と学習を繰り返しながら、より良い成果を生み出すための方法の1つです。

docs/spec.md（仕様） 
# 仕様：KPT 振り返りボード

## 目的
スプリントの振り返りで、チーム全員が Keep / Problem / Try を書き出して共有できるようにする。

## ユーザーストーリー
- 開発者として、振り返りで気づいたことをカードにして追加したい。思いついたその場で書き留めるため。
- スクラムマスターとして、Keep / Problem / Try ごとの枚数を見たい。どこに話し合いの時間を使うか決めるため。

## 機能
1. 種類（Keep / Problem / Try）を選んで、ひとことのカードを追加できる
2. カードは種類ごとの列に表示される
3. 各列に、その種類のカードの枚数を表示する
4. カードはブラウザに保存され、再読み込みしても残る

## 受け入れ条件
- カードの本文は、前後の空白を取り除いたうえで 1〜140 文字
- 本文が空、または 140 文字を超える場合は、エラーメッセージを表示して追加しない
- 種類は keep / problem / try のどれか
- 入力された本文は、そのまま文字として表示される（HTML として解釈されない）

## 対象外（今回は作らない）
- カードの編集・削除
- 複数人でのリアルタイム共有
AGENTS.md（AI への作業ルール） 
# AGENTS.md

このリポジトリで作業する AI エージェント向けのルールです。

## プロジェクト
スプリントの振り返りで使う、ブラウザだけで動く KPT ボード。
**仕様は `docs/spec.md` にあります。作業の前に必ず読んでください。**

## コマンド
- テスト：`npm test`
- 画面の確認：`python3 -m http.server 8000` → http://localhost:8000

## ファイル構成
- `src/kpt.js` … ロジック（DOM を使わない。テスト対象）
- `src/app.js` … 画面の処理
- `index.html` / `style.css`
- `tests/` … テスト（受け入れ条件を確かめる）

## 守ること
- フレームワークやライブラリは使わない（HTML / CSS / JavaScript だけ）
- 仕様は docs/spec.md にある。作業の前に必ず読む
- テストは Node.js に最初から入っている node --test を使う
- テストを書き換えて通すことはしない。
  テストと仕様が合わない場合は、作業を止めて人間に確認する
- 仕様にない機能は勝手に足さない
- 変更したら `npm test` を実行し、結果を報告する
- 返答は日本語で

## レビュー
レビューを頼まれたら、`.claude/skills/` のスキルを使う。
- `kpt-security` … セキュリティ
- `kpt-efficiency` … 効率
- `kpt-quality` … 品質（仕様・テスト）
- `kpt-review` … 3つを別々のレビュアーで同時に

# セキュリティレビュー

`src/` と `index.html` を読み、脆弱性を探します。**コードは書き換えません。**
