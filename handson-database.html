実践編：データベースでTodo管理

マイグレーション・モデル・リポジトリをTDDで構築

実務で使える本格的なデータベース連携をテスト駆動で学ぶ

配列からデータベースへ

🎯 この章の目的

前章では配列でTodo管理を実装しました。
しかし、実際のアプリケーションではデータベースを使います。

配列版の問題点

  • ❌ アプリを再起動するとデータが消える
  • ❌ 複数のユーザーでデータを共有できない
  • ❌ 大量のデータを扱えない
  • ❌ 実務では使えない

📚 学べること

Laravel基礎

  • • マイグレーションの作成
  • • Eloquentモデル
  • • データベース操作

テスト技術

  • • RefreshDatabaseトレイト
  • • テストデータの作成
  • • DB用アサーション

設計パターン

  • • リポジトリパターン
  • • 依存性注入（DI）
  • • レイヤードアーキテクチャ

実践スキル

  • • SQLite（テスト用DB）
  • • データベース設計
  • • 実務レベルのTDD

💡 TDDの流れ

まずテストを書いてから、マイグレーション→モデル→リポジトリの順に実装します。
テストファーストで進めることで、設計ミスを早期に発見できます。

ステップ0：環境準備

データベース接続とテスト環境を確認する

🔌 データベースクライアントツールの接続確認

Sequel Ace、A5M2、またはそれに準ずるDBクライアントツールで、
MySQLデータベースに接続できることを確認してください。

📖 接続情報（環境構築編と同じ）：

  • ホスト: 127.0.0.1 (または localhost)
  • ポート: 3386
  • ユーザー名: udemy123
  • パスワード: pass123
  • データベース: laravel

※ ポートは 3306 ではなく 3386 です（docker-compose.yml でホスト側に公開しているポート）。

💡 ポイント: DBクライアントツールを使うことで、テーブル構造やデータの確認が簡単になります。

📝 phpunit.xml の設定確認

テスト用のデータベース設定を確認します。
src/phpunit.xmlを開き、以下の2行が有効になっている（コメントアウトされていない）ことを確認してください。テンプレートには最初から入っています。 

<!-- src/phpunit.xml（抜粋） -->
<php>
    ...
    <env name="DB_CONNECTION" value="sqlite"/>
    <env name="DB_DATABASE" value=":memory:"/>
    ...
</php>

📖 設定の意味：

  • テスト実行時だけ、メモリ上のSQLiteデータベースが使われます（高速で、終わると消えます）
  • ブラウザで動かすアプリ本体は、これまでどおり.envのMySQLを使います
  • RefreshDatabaseトレイトにより、テストごとにまっさらなテーブルが用意されます

⚠️ 注意: この2行をコメントアウトすると、テストが開発用のMySQLに対して実行され、RefreshDatabaseによって開発用DBのデータが消えます。そのままにしておきましょう。

✅ 準備完了

これでテスト用のデータベース環境が整いました。次は実装に進みます。
この章の php artisan コマンドも、docker compose exec app bash でコンテナに入ってから実行してください。

ステップ1：マイグレーション作成

todosテーブルを設計する

📊 テーブル設計

まず、どんなデータを保存するか決めます。

todosテーブルのカラム

カラム名 型 説明
id BIGINT 主キー（自動採番）
title VARCHAR(255) Todoのタイトル
completed BOOLEAN 完了フラグ（デフォルトfalse）
created_at TIMESTAMP 作成日時
updated_at TIMESTAMP 更新日時

🔧 マイグレーションファイルを作成

以下のコマンドを実行します。 

php artisan make:migration create_todos_table

src/database/migrations/YYYY_MM_DD_HHMMSS_create_todos_table.phpが作成されます。

✏️ マイグレーションファイルを編集

<?php

use Illuminate\Database\Migrations\Migration;
use Illuminate\Database\Schema\Blueprint;
use Illuminate\Support\Facades\Schema;

return new class extends Migration
{
    /**
     * マイグレーションを実行
     */
    public function up(): void
    {
        Schema::create('todos', function (Blueprint $table) {
            $table->id();
            $table->string('title');
            $table->boolean('completed')->default(false);
            $table->timestamps();
        });
    }

    /**
     * マイグレーションをロールバック
     */
    public function down(): void
    {
        Schema::dropIfExists('todos');
    }
};

📖 コードの解説：

  • $table->id() - 主キー（BIGINT UNSIGNED AUTO_INCREMENT）
  • $table->string('title') - VARCHAR(255)
  • $table->boolean('completed')->default(false) - BOOLEAN型、デフォルト値false
  • $table->timestamps() - created_atとupdated_atを自動追加

▶️ マイグレーションを実行

開発環境のデータベースにテーブルを作成します。 

php artisan migrate

✅ 成功すると「Running migrations.」に続いて ..._create_todos_table の行に「DONE」と表示されます。
これでtodosテーブルがデータベースに作成されました。

ステップ2：Eloquentモデル作成

Todoデータを扱うモデルを作る

🔧 モデルファイルを作成

以下のコマンドを実行します。 

php artisan make:model Todo

src/app/Models/Todo.phpが作成されます。

✏️ モデルファイルを編集

<?php

namespace App\Models;

use Illuminate\Database\Eloquent\Model;

class Todo extends Model
{
    /**
     * 複数代入可能な属性
     */
    protected $fillable = [
        'title',
        'completed',
    ];

    /**
     * 属性のキャスト
     */
    protected $casts = [
        'completed' => 'boolean',
    ];
}

📖 コードの解説：

  • $fillable - 一括代入を許可するカラムを指定（セキュリティ対策）
  • $casts - データベースの値をPHPの型に変換（'0'/'1' → true/false）
  • extends Model - Eloquentの機能を継承（CRUD操作が簡単に）

💡 Eloquentとは？

LaravelのORM（Object-Relational Mapping）です。
SQLを書かずに、PHPのメソッドでデータベース操作ができます。

例：

Todo::create(['title' => '買い物']);
$todos = Todo::all();
$todo->update(['completed' => true]);

Todoを作成できることをテストする

RED

テストファイルを作成

Todoモデルのテストを作成します。 

php artisan make:test TodoTest --unit

src/tests/Unit/TodoTest.phpを開いて、最初のテストを書きます。 

<?php

namespace Tests\Unit;

use Tests\TestCase;
use PHPUnit\Framework\Attributes\Test;
use Illuminate\Foundation\Testing\RefreshDatabase;
use App\Models\Todo;

class TodoTest extends TestCase
{
    use RefreshDatabase;

    /**
     * Todoを作成できることをテストする
     */
    #[Test]
    public function it_can_create_a_todo()
    {
        // Arrange & Act
        $todo = Todo::create([
            'title' => '買い物に行く',
            'completed' => false,
        ]);

        // Assert
        $this->assertDatabaseHas('todos', [
            'title' => '買い物に行く',
            'completed' => false,
        ]);

        $this->assertEquals('買い物に行く', $todo->title);
        $this->assertFalse($todo->completed);
    }
}

📖 重要な要素の解説:

use RefreshDatabase;

テスト実行時にデータベースをリフレッシュ（テーブルを再作成）します。
これにより、テスト間でデータが干渉しません。

assertDatabaseHas('todos', [...])

データベースに指定したデータが存在することを確認します。

Todo::create([...])

Eloquentでデータを作成します。SQLのINSERT文を自動生成します。

テストを実行します。

php artisan test tests/Unit/TodoTest.php

✅ 成功するはず：

マイグレーションとモデルがすでに作成されているため、テストは成功します。
これがデータベーステストの基本形です。

ステップ4：リポジトリパターンを導入

ビジネスロジックとDB操作を分離する

🤔 なぜリポジトリパターンが必要？

❌ 悪い例：コントローラで直接DB操作

public function store(Request $request)
{
    $todo = Todo::create([
        'title' => $request->title
    ]);

    return response()->json($todo);
}

問題点：
• コントローラが肥大化
• テストが書きにくい
• 再利用できない

✅ 良い例：リポジトリ経由でDB操作

public function store(
    Request $request,
    TodoRepository $repo
) {
    $todo = $repo->create(
        $request->title
    );

    return response()->json($todo);
}

メリット：
• 役割が明確
• テストしやすい
• 再利用可能

📚 リポジトリパターンとは？

データベース操作を専用のクラス（リポジトリ）にまとめるデザインパターンです。
レイヤードアーキテクチャの一部で、実務では標準的に使われます。

RED

リポジトリのテストを書く

まずはテストを書きます。 

php artisan make:test TodoRepositoryTest --unit
<?php

namespace Tests\Unit;

use Tests\TestCase;
use PHPUnit\Framework\Attributes\Test;
use Illuminate\Foundation\Testing\RefreshDatabase;
use App\Repositories\TodoRepository;
use App\Models\Todo;

class TodoRepositoryTest extends TestCase
{
    use RefreshDatabase;

    private TodoRepository $repository;

    protected function setUp(): void
    {
        parent::setUp();
        $this->repository = new TodoRepository();
    }

    /**
     * Todoを作成できることをテストする
     */
    #[Test]
    public function it_can_create_a_todo()
    {
        // Arrange & Act
        $todo = $this->repository->create('買い物に行く');

        // Assert
        $this->assertDatabaseHas('todos', [
            'title' => '買い物に行く',
            'completed' => false,
        ]);
        $this->assertInstanceOf(Todo::class, $todo);
    }

    /**
     * 全Todoを取得できることをテストする
     */
    #[Test]
    public function it_can_get_all_todos()
    {
        // Arrange
        Todo::create(['title' => '買い物', 'completed' => false]);
        Todo::create(['title' => '掃除', 'completed' => false]);

        // Act
        $todos = $this->repository->getAll();

        // Assert
        $this->assertCount(2, $todos);
    }

    /**
     * Todoを完了にできることをテストする
     */
    #[Test]
    public function it_can_complete_a_todo()
    {
        // Arrange
        $todo = Todo::create(['title' => '買い物', 'completed' => false]);

        // Act
        $this->repository->complete($todo->id);

        // Assert
        $this->assertDatabaseHas('todos', [
            'id' => $todo->id,
            'completed' => true,
        ]);
    }

    /**
     * 未完了Todoだけを取得できることをテストする
     */
    #[Test]
    public function it_can_get_pending_todos()
    {
        // Arrange
        Todo::create(['title' => '買い物', 'completed' => false]);
        $completed = Todo::create(['title' => '掃除', 'completed' => false]);
        $completed->update(['completed' => true]);

        // Act
        $pending = $this->repository->getPending();

        // Assert
        $this->assertCount(1, $pending);
        $this->assertEquals('買い物', $pending[0]->title);
    }

    /**
     * Todoを削除できることをテストする
     */
    #[Test]
    public function it_can_delete_a_todo()
    {
        // Arrange
        $todo = Todo::create(['title' => '買い物', 'completed' => false]);

        // Act
        $this->repository->delete($todo->id);

        // Assert
        $this->assertDatabaseMissing('todos', [
            'id' => $todo->id,
        ]);
    }
}

📖 新しいアサーション：

  • assertInstanceOf(Todo::class, $todo) - 返り値がTodoクラスのインスタンスか確認
  • assertDatabaseMissing('todos', [...]) - データベースに指定データが存在しないことを確認
  • setUp() - 各テスト実行前に呼ばれるメソッド（リポジトリを初期化）
GREEN

リポジトリを実装

src/app/Repositories/TodoRepository.phpを作成します。
（Repositoriesディレクトリを手動で作成してください） 

<?php

namespace App\Repositories;

use App\Models\Todo;
use Illuminate\Database\Eloquent\Collection;

class TodoRepository
{
    /**
     * Todoを作成する
     */
    public function create(string $title): Todo
    {
        return Todo::create([
            'title' => $title,
        ]);
    }

    /**
     * 全てのTodoを取得する
     */
    public function getAll(): Collection
    {
        return Todo::all();
    }

    /**
     * Todoを完了にする
     */
    public function complete(int $id): bool
    {
        $todo = Todo::find($id);

        if (!$todo) {
            return false;
        }

        return $todo->update(['completed' => true]);
    }

    /**
     * 未完了のTodoを取得する
     */
    public function getPending(): Collection
    {
        return Todo::where('completed', false)->get();
    }

    /**
     * Todoを削除する
     */
    public function delete(int $id): bool
    {
        $todo = Todo::find($id);

        if (!$todo) {
            return false;
        }

        return $todo->delete();
    }
}

📖 Eloquentメソッドの解説：

  • Todo::create([...]) - INSERT文を実行
  • Todo::all() - 全レコードをSELECT
  • Todo::find($id) - 主キーで検索（SELECT WHERE id = ?）
  • Todo::where('completed', false)->get() - 条件付きSELECT
  • $todo->update([...]) - UPDATEを実行
  • $todo->delete() - DELETEを実行

ステップ5：コントローラーとViewを作成

実際にブラウザで動くTodoアプリを作る

🎯 ゴール

これまで作ったリポジトリを使って、実際にブラウザで動くTodoアプリを作ります。

実装する機能

  • ✓ Todo一覧表示
  • ✓ Todo追加フォーム
  • ✓ Todo完了チェックボックス
  • ✓ Todo削除ボタン

🔧 コントローラーを作成

php artisan make:controller TodoController

src/app/Http/Controllers/TodoController.phpを編集します。 

<?php

namespace App\Http\Controllers;

use Illuminate\Http\Request;
use App\Repositories\TodoRepository;

class TodoController extends Controller
{
    private TodoRepository $repository;

    public function __construct(TodoRepository $repository)
    {
        $this->repository = $repository;
    }

    /**
     * Todo一覧を表示
     */
    public function index()
    {
        $todos = $this->repository->getAll();
        return view('todos.index', compact('todos'));
    }

    /**
     * Todoを追加
     */
    public function store(Request $request)
    {
        $request->validate([
            'title' => 'required|max:255',
        ]);

        $this->repository->create($request->title);

        return redirect()->route('todos.index')
            ->with('success', 'Todoを追加しました');
    }

    /**
     * Todoを完了にする
     */
    public function complete(int $id)
    {
        $this->repository->complete($id);

        return redirect()->route('todos.index')
            ->with('success', 'Todoを完了にしました');
    }

    /**
     * Todoを削除
     */
    public function destroy(int $id)
    {
        $this->repository->delete($id);

        return redirect()->route('todos.index')
            ->with('success', 'Todoを削除しました');
    }
}

📖 コードの解説：

  • __construct(TodoRepository $repository) - 依存性注入（DI）でリポジトリを受け取る
  • $request->validate([...]) - バリデーション（必須チェック、文字数制限）
  • view('todos.index', compact('todos')) - Bladeテンプレートにデータを渡す
  • redirect()->route('todos.index')->with(...) - リダイレクトとフラッシュメッセージ

🛤️ ルート設定

src/routes/web.phpに以下を追加します。 

use App\Http\Controllers\TodoController;

Route::get('/todos', [TodoController::class, 'index'])->name('todos.index');
Route::post('/todos', [TodoController::class, 'store'])->name('todos.store');
Route::post('/todos/{id}/complete', [TodoController::class, 'complete'])->name('todos.complete');
Route::delete('/todos/{id}', [TodoController::class, 'destroy'])->name('todos.destroy');

RESTfulな設計：
GET /todos → 一覧表示
POST /todos → 作成
POST /todos/{id}/complete → 完了
DELETE /todos/{id} → 削除

📖 Bladeテンプレートの構文：

  • @csrf - CSRF保護トークン（必須）
  • @if(条件) ... @endif - 条件分岐
  • @foreach($todos as $todo) ... @endforeach - ループ
  • @method('DELETE') - HTTPメソッド偽装
  • {{ $変数 }} - HTMLエスケープして出力
  • @error('フィールド名') - バリデーションエラー表示
