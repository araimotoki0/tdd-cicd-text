💻 必要なパソコンのスペック

項目 必要な条件
OS Windows 11（23H2 / build 22631 以降）を推奨
Windows 10 は 22H2（build 19045）が Docker のサポート対象ですが、 Microsoft のサポートが 2025年10月14日に終了しているため、 Windows 11 へのアップグレードを推奨します
CPU 64bit・SLAT対応のCPU（4コア以上推奨）
BIOS/UEFIで仮想化支援機能（Intel VT-x / AMD-V）が有効であること
メモリ 8GB以上が必須（16GB推奨）
Docker Desktop for Windows の公式最低要件が8GBです。 WSL2・Docker・エディタ・ブラウザを同時に開くため、16GBあると快適です
空き容量 20GB以上
Docker Desktop本体とWSL2に加え、この研修で使うコンテナイメージだけで 約1.7GB使います（PHP 835MB / MySQL 812MB / nginx 62MB）。 作業領域を含めて余裕をもって確保してください
ネットワーク インターネット接続（数GBのダウンロードが発生します）
社内プロキシ環境では追加設定が必要になる場合があります

🔑 インストールには管理者権限が必要です

Windowsの場合、特にWSL2の有効化で管理者権限が必須です。

  • • WSL2の有効化 - wsl --install を管理者として実行する必要があります
  • • BIOS/UEFIの仮想化設定 - 無効になっている場合、変更にはPC起動時のBIOS操作が必要です
  • • Docker Desktop - ユーザー単位のインストールなら管理者権限は不要ですが、 多くの企業ではソフトウェアのインストール自体が制限されています

管理者権限がないアカウントでは、WSL2 を有効化できず研修を進められません。

🏢 会社のパソコンで参加される方へ

会社から貸与されているパソコンの場合、 セキュリティポリシーによってソフトウェアのインストールが制限されていることがあります。 その場合、研修を進めることができません。

事前にご確認ください

  • ☑️ 管理者権限を持つアカウントでログインできますか？
  • ☑️ WSL2 を有効化できますか？（BIOSの仮想化設定を含む）
  • ☑️ 会社の規定として、Docker Desktop をインストールしてよいですか？
  • ☑️ 情報システム部門の許可・申請が必要ではありませんか？

申請が必要な場合、承認までに数日〜数週間かかることがあります。お早めにご確認ください。

💡 個人のパソコンでのご参加もおすすめです

ご自身のパソコンで参加していただくのも、とても良い選択です。 権限を気にせず自由に環境を作れますし、研修が終わったあとも そのまま自分の学習環境として使い続けられます。

2️⃣ WSL2 + Ubuntu のインストール

💡 WSL2とは？

Windows Subsystem for Linux 2 - WindowsとLinuxを同時に実行できる技術です。

  • • 実際のLinuxカーネルが軽量仮想マシン上で動作
  • • WindowsとLinuxのファイルシステムを相互にアクセス可能
  • • Dockerの実行に必要
  • • 本番環境（Linux）と同じ環境で開発できる

WSL2の仕組み - シンプルに理解する

Windows 11

アプリ、エクスプローラー、VSCode

Ubuntu (Linux)

Docker、Git、Antigravity CLI

Hyper-V（仮想化レイヤー）

両方のOSがこの層を通じてハードウェアにアクセス

物理ハードウェア

CPU、メモリ、SSD、ネットワーク

🔑 重要: WindowsもLinuxも、両方ともHyper-V経由で同じハードウェアにアクセスします。これにより両者が対等な立場で動作し、ほぼネイティブに近い速度を実現しています。

インストール手順

  1. 1. PowerShellを管理者権限で開く

    スタートメニュー → 「PowerShell」を右クリック → 「管理者として実行」

  2. 2. 以下のコマンドを実行 
    wsl --install

    このコマンドで自動的にUbuntuもインストールされます

  3. 3. PCを再起動
  4. 4. 初回起動でユーザー名とパスワードを設定

    Ubuntuが自動で起動するので、Linuxのユーザー名とパスワードを設定します

確認コマンド

PowerShellで実行:

wsl --version

⚠️ 注意: WSL2はWindows 10バージョン2004以降、またはWindows 11が必要です。

3️⃣ Git の確認と初期設定

✅ すでに入っていることが多いです

Microsoft公式ドキュメントによると、 多くのWSLディストリビューションにはGitが最初から入っています。 まずは確認コマンドを実行してください。

表示されればインストールは不要です。そのまま「初期設定」に進んでください。

💡 重要: GitはWSL2（Ubuntu）内のものを使います。 Windows側とWSL2側は別々のファイルシステムなので、Gitもそれぞれ独立しています。

確認コマンド

WSL2（Ubuntu）内で実行:

git --version

表示されなかった場合のみ実行

「command not found」と出た場合だけ、以下でインストールします:

sudo apt update && sudo apt install -y git

初期設定（こちらは必須です）

Gitを使うために、ユーザー名とメールアドレスを設定します。

git config --global user.name "あなたの名前"
git config --global user.email "your.email@example.com"
git config --list

GitHub CLI（gh）のインストールとログイン（こちらも必須です）

CI/CD 講座で .github/workflows/ のファイルを push するとき、GitHub は workflow という権限を求めます。 いま gh でログインして、この権限を付けておくと、講座当日に push で止まりません。 

sudo apt update && sudo apt install -y gh
gh --version
gh auth login -h github.com -s workflow

質問には、HTTPS → Yes（Git の認証も gh に任せる）→ Login with a web browser の順に答えます。 表示されたコードをブラウザに貼って、自分の GitHub アカウントで承認してください。
WSL2（Ubuntu）内で実行します。gh が見つからないと出た場合は、公式のインストール手順（Debian/Ubuntu）のコマンドを使ってください。

確認コマンド

gh auth status

Token scopes: の行に workflow が入っていればOKです。 入っていない人は gh auth refresh -h github.com -s workflow を実行してください。

5️⃣ Antigravity CLI のインストールと基本操作

✅ 無料で利用可能！

個人のGoogleアカウント（@gmail.com）があれば、クレジットカード登録なしで無料で使えます。

本講座で Antigravity CLI を推奨している理由は、無料だからです。
※ Gemini CLI は2026年6月18日に無料版・Google AI Pro／Ultra 向けの提供を終了しました。本講座では後継の Antigravity CLI を使います。

💡 使い慣れているものがあればそちらでOK

Claude Code や Codex など、すでに使い慣れているものがあれば、それを使っていただいても構いません。 その場合はこのセクションのインストール作業は不要です。

公式サイト・ドキュメント

https://antigravity.google/ https://antigravity.google/docs/cli/install（インストール手順）

⚠️ 必ず WSL2（Ubuntu）内にインストールしてください

Laravelのプロジェクトは WSL2 側に置くため、AIにコードを読ませるには CLIも WSL2 側にある必要があります。

公式には Windows（PowerShell／コマンドプロンプト）用のインストーラーもありますが、本研修では使いません。 Windows側に入れるとWSL2内のファイルを扱いづらくなります。

インストールコマンド

WSL2（Ubuntu）内で実行:

curl -fsSL https://antigravity.google/cli/install.sh | bash

Node.js や npm は不要です。単体の実行ファイルとして ~/.local/bin/agy に配置されます。 コマンド名は agy です。

⚠️ PATHが通っていない場合: ~/.local/bin がPATHに含まれていないと、 インストーラーが「シェル設定ファイルに追記する1行」を表示します。その行を ~/.bashrc に追記し、 source ~/.bashrc を実行するか、ターミナルを開き直してください。

インストール確認

ターミナルを一度閉じて開き直してから実行してください。

agy --version

1.3.3 のようにバージョンが表示されれば成功です（2026年10月時点は 1.3 系）。
すでにインストール済みの人は agy update で最新版にしておきましょう。

初回起動とログイン

agy
  1. 1. ログイン方法の選択画面で 「1. Google OAuth」を選んで Enter （「2. Use a Google Cloud project」は会社のGCP向けで、本講座では使いません）
  2. 2. ブラウザが開くので、個人のGoogleアカウントでログイン（認証コードが表示されたら、ターミナルに貼り付けて Enter）。 WSL2からブラウザが自動で開かない場合は、表示された認証用URLを Windows 側のブラウザで開きます
  3. 3. 色テーマの選択・利用規約への同意・フォルダの信頼（Trust）を済ませ、入力欄が表示されれば成功

※ ログイン情報は保存され、次回からは自動でログインされます。
※ 終了は /exit、ログアウトは /logout です。

⚠️ 重要: 個人アカウントでログイン

必ず個人のGoogleアカウント（@gmail.com）でログインしてください。 会社（Google Workspace）のアカウントは、会社の設定によってはログインできないことがあります。

🔄 Googleアカウントを複数お持ちの方は、必ず切り替えてください

認証時に開くブラウザが会社のアカウントでログインしたままになっていると、 アカウント選択の画面が出ずに、そのまま会社のアカウントで進んでしまうことがあります。

確実に切り替える方法

  1. 1. 認証画面が出たら、表示されているアカウントのメールアドレスを必ず確認する
  2. 2. 会社のアカウントだったら「別のアカウントを使用」を選び、個人の @gmail.com に切り替える
  3. 3. アカウント選択画面が出ない場合は、認証用URLをコピーして シークレットウィンドウ（プライベートウィンドウ）に貼り付けて開く

間違ったアカウントでログインしてしまった場合:
CLI内で /logout を実行してから、 もう一度 agy を起動してやり直してください。

🔑 Googleログインできない人は APIキーで（研修当日に講師が貸し出します）

APIキーで使うには、次の2つの設定が両方とも必要です（片方だけでは動きません）。

  1. ① ~/.gemini/antigravity-cli/settings.json に "modelProvider": "gemini" を追加する
  2. ② 環境変数 GEMINI_API_KEY にキーを入れて、同じターミナルで agy を起動する
export GEMINI_API_KEY="講師から受け取ったキー"
agy

※ GOOGLE_API_KEY や .env ファイルは読まれません。
※ 詳しい手順は研修中に「Antigravity CLI」のページで説明します。

📊 無料枠はどのくらい？

  • • 無料（Pro／Ultra 以外） - 一定量が1週間ごとに回復
  • • Google AI Pro／Ultra - 多めの量が5時間ごとに回復（週の上限まで）

※ 具体的な回数は公開されておらず、予告なく変わることがあります。

⚠️ 消費が想像より早い点に注意
1回の指示で裏側の複数エージェントが動くため、体感より早く消費します。 無料枠は週単位でしか回復しないので、研修の前に使い切らないよう注意してください。

残量はCLI内で /usage を実行すると確認できます。

🎯 どのモデルを使えばいい？

研修では Gemini 3.8 Flash を使います。モデルはCLI内の /model で切り替えられます。

  • • Gemini 3.8 Flash - 最新の標準モデル。速くて賢い。研修ではこれ
  • • Gemini 3.1 Pro - 難しい設計・推論向け。応答は遅め、消費も大きい
  • • Gemini 3.7 / 3.6 / 3.5 Flash - ひとつ前の世代。特に理由がなければ選ばなくてOK

※ モデル名の後ろの High / Medium / Low は「どれだけ深く考えるか」です。既定は Medium で、迷ったらそのままで構いません。 /effort で変更できます。

よく使うコマンド

ターミナルで実行するコマンド

  • • agy - CLIを起動
  • • agy --version - バージョン確認
  • • agy update - 最新版に更新
  • • agy changelog - 更新履歴を表示

CLI起動中に使うスラッシュコマンド

  • • /help - ヘルプ・コマンド一覧
  • • /model ／ /effort - モデル・考える深さの切り替え
  • • /usage - 残りの使用量（クォータ）を確認
  • • /diff - 変更差分を表示
  • • /resume - 前の会話を再開
  • • /logout - ログアウト
  • • /exit - 終了

ファイル指定方法 (`@`マーク)

プロンプト内で `@` に続けてファイルパスを入力すると、そのファイルをコンテキストとして Antigravity CLI に渡すことができます。これにより、ファイルの内容に基づいた質問や指示が可能になります。

単一ファイルの例:

@routes/web.php このファイルを解説して

複数ファイルの例:

@app/Models/User.php @app/Http/Controllers/UserController.php リレーション確認

クローンコマンド

WSL2（Ubuntu）内で実行:

mkdir -p ~/Documents   # Ubuntu には最初はないので作成（あればそのまま）
cd ~/Documents
git clone https://github.com/あなたのユーザー名/リポジトリ名.git
cd リポジトリ名

環境ファイル準備

cp .env.example .env

Docker立ち上げと権限設定

# Dockerコンテナ起動
docker compose up -d

# rootユーザーでコンテナに入る
docker compose exec -u root app bash

# /dataの所有者をappuserに変更
chown -R appuser:appuser /data

# exitして通常ユーザーで入り直す
exit

💡 Laravel はすでに src/ に入っています。
composer create-project を実行する必要はありません。 ただし vendor/ と .env は Git管理外のため、 初回だけ次のセットアップが必要です。

Laravelの初回セットアップ

コンテナに入って実行します:

docker compose exec app bash

composer install
cp .env.example .env
php artisan key:generate
php artisan migrate

exit

src/.env.example には DBの接続先（DB_HOST=db など）が設定済みなので、 コピーするだけで接続できます。

データベース設定

✅ 設定済みです

前の手順で cp .env.example .env を実行していれば、 DBの接続設定はすでに完了しています。書き換えは不要です。

設定内容（src/.env）

中身は次のようになっています。確認だけしておきましょう。

DB_CONNECTION=mysql
DB_HOST=db
DB_PORT=3306
DB_DATABASE=laravel
DB_USERNAME=udemy123
DB_PASSWORD=pass123

⚠️ DB_HOST は db です。 127.0.0.1 や localhost ではありません。 アプリはコンテナの中で動いており、同じDockerネットワーク上の db というコンテナ名で接続するためです。

接続確認

docker compose exec app php artisan migrate:status

✅ 確認

ブラウザで以下のURLにアクセス:

http://localhost:8086

Laravelの初期画面が表示されれば成功です。
テストも動かしてみましょう: docker compose exec app php artisan test

よくあるトラブルと対処法

トラブル1: WSL 2エラー

エラー: "WSL 2 installation is incomplete"

解決策:

  1. 1. PowerShellを管理者権限で開く
  2. 2. 以下のコマンドを実行:
wsl --install
wsl --set-default-version 2

3. PCを再起動してDocker Desktopを再度起動

トラブル2: ポート番号被り

エラー: "address already in use"

解決策: 他のアプリと番号がぶつかっています。docker-compose.yml の ports の左側（パソコン側）の番号を変えて、docker compose up -d し直します。

ports:
  - ${WEB_PORT:-8086}:80       # Webサーバー（8086 → 8087 などに）
  - 127.0.0.1:3386:3306        # MySQL（3386 → 3387 などに）

Web を 8087 に変えた場合のアクセスURL: http://localhost:8087

トラブル3: Docker未起動

エラー: "Cannot connect to the Docker daemon"

解決策: スタートメニューからDocker Desktopを起動します。タスクバーにDockerアイコンが表示されていることを確認してください。

トラブル4: .env設定誤り

エラー: "SQLSTATE[HY000]"

解決策: src/.envの設定値をdocker-compose.ymlと一致させて再起動します。

docker compose down -v
docker compose up -d

トラブル5: ボリュームの問題

症状: 古い設定が残っている

解決策: -vオプション付きで削除します。

docker compose down -v
docker compose up -d
docker compose exec app bash
php artisan migrate

⚠️ 警告: 本番環境では-vオプションは使用禁止です！

トラブル6: VSCodeがWSLに接続できない

症状: 「WSL: Ubuntu」と表示されない

解決策:

  1. 1. WSL拡張機能が正しくインストールされているか確認
  2. 2. VSCodeを再起動
  3. 3. PowerShell で wsl --shutdown を実行してから、WSL2（Ubuntu）を起動し直す

トラブル7: Laravel の権限エラー（Permission denied）

症状: ブラウザで開くと The stream or file "/data/storage/logs/laravel.log" could not be opened ... Permission denied や 403 / 500 エラーが出る

原因: コンテナの中の Laravel（ユーザー appuser）が、storage や bootstrap/cache にファイルを書き込めない

解決策: リポジトリのフォルダ（docker-compose.yml がある場所）で、持ち主と書き込み権限を直します。

docker compose exec -u root app chown -R appuser:appuser /data
docker compose exec -u root app chmod -R 775 /data/storage /data/bootstrap/cache

それでもファイルが読めないエラーや 403 が出るときは、ファイルに読み取り権限を付けます。

chmod -R 755 src

⚠️ 注意: chmod -R 777 は誰でも書き換えられる状態になるので使わないでください。
