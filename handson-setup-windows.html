💻 必要なパソコンのスペック

項目 必要な条件
OS Windows 11（23H2 / build 22631 以降）を推奨
Windows 10 は 22H2（build 19045）が Docker のサポート対象ですが、 Microsoft のサポートが 2025年10月14日に終了しているため、 Windows 11 へのアップグレードを推奨します
CPU 64bit・SLAT対応のCPU（4コア以上推奨）
BIOS/UEFIで仮想化支援機能（Intel VT-x / AMD-V）が有効であること
メモリ 8GB以上が必須（16GB推奨）
Docker Desktop for Windows の公式最低要件が8GBです。 WSL2・Docker・エディタ・ブラウザを同時に開くため、16GBあると快適です
空き容量 20GB以上
Docker Desktop本体とWSL2に加え、この研修で使うコンテナイメージだけで 約1.7GB使います（PHP 835MB / MySQL 812MB / nginx 62MB）。 作業領域を含めて余裕をもって確保してください
ネットワーク インターネット接続（数GBのダウンロードが発生します）
社内プロキシ環境では追加設定が必要になる場合があります

🔑 インストールには管理者権限が必要です

Windowsの場合、特にWSL2の有効化で管理者権限が必須です。

  • • WSL2の有効化 - wsl --install を管理者として実行する必要があります
  • • BIOS/UEFIの仮想化設定 - 無効になっている場合、変更にはPC起動時のBIOS操作が必要です
  • • Docker Desktop - ユーザー単位のインストールなら管理者権限は不要ですが、 多くの企業ではソフトウェアのインストール自体が制限されています

管理者権限がないアカウントでは、WSL2 を有効化できず研修を進められません。

🏢 会社のパソコンで参加される方へ

会社から貸与されているパソコンの場合、 セキュリティポリシーによってソフトウェアのインストールが制限されていることがあります。 その場合、研修を進めることができません。

事前にご確認ください

  • ☑️ 管理者権限を持つアカウントでログインできますか？
  • ☑️ WSL2 を有効化できますか？（BIOSの仮想化設定を含む）
  • ☑️ 会社の規定として、Docker Desktop をインストールしてよいですか？
  • ☑️ 情報システム部門の許可・申請が必要ではありませんか？

申請が必要な場合、承認までに数日〜数週間かかることがあります。お早めにご確認ください。

💡 個人のパソコンでのご参加もおすすめです

ご自身のパソコンで参加していただくのも、とても良い選択です。 権限を気にせず自由に環境を作れますし、研修が終わったあとも そのまま自分の学習環境として使い続けられます。

会社のパソコンで制限に引っかかりそうな方は、無理をせず個人のパソコンをご用意ください。

2️⃣ WSL2 + Ubuntu のインストール

💡 WSL2とは？

Windows Subsystem for Linux 2 - WindowsとLinuxを同時に実行できる技術です。

  • • 実際のLinuxカーネルが軽量仮想マシン上で動作
  • • WindowsとLinuxのファイルシステムを相互にアクセス可能
  • • Dockerの実行に必要
  • • 本番環境（Linux）と同じ環境で開発できる

WSL2の仕組み - シンプルに理解する

Windows 11

アプリ、エクスプローラー、VSCode

Ubuntu (Linux)

Docker、Git、Antigravity CLI

Hyper-V（仮想化レイヤー）

両方のOSがこの層を通じてハードウェアにアクセス

物理ハードウェア

CPU、メモリ、SSD、ネットワーク

🔑 重要: WindowsもLinuxも、両方ともHyper-V経由で同じハードウェアにアクセスします。これにより両者が対等な立場で動作し、ほぼネイティブに近い速度を実現しています。

インストール手順

  1. 1. PowerShellを管理者権限で開く

    スタートメニュー → 「PowerShell」を右クリック → 「管理者として実行」

  2. 2. 以下のコマンドを実行 
    wsl --install

    このコマンドで自動的にUbuntuもインストールされます

  3. 3. PCを再起動
  4. 4. 初回起動でユーザー名とパスワードを設定

    Ubuntuが自動で起動するので、Linuxのユーザー名とパスワードを設定します

確認コマンド

PowerShellで実行:

wsl --version

⚠️ 注意: WSL2はWindows 10バージョン2004以降、またはWindows 11が必要です。

5️⃣ Antigravity CLI のインストールと基本操作

✅ 無料で利用可能！

個人のGoogleアカウント（@gmail.com）があれば、クレジットカード登録なしで無料で使えます。

本講座で Antigravity CLI を推奨している理由は、無料だからです。

💡 使い慣れているものがあればそちらでOK

Claude Code や Codex など、すでに使い慣れているものがあれば、それを使っていただいても構いません。 その場合はこのセクションのインストール作業は不要です。

⚠️ 重要: 個人アカウントでログイン

必ず個人のGoogleアカウント（@gmail.com）でログインしてください。 Google Workspace（会社）アカウントは現在サポート対象外で、 「account not eligible」というエラーになります。

🔄 Googleアカウントを複数お持ちの方は、必ず切り替えてください

認証時に開くブラウザが会社のアカウントでログインしたままになっていると、 アカウント選択の画面が出ずに、そのまま会社のアカウントで進んでしまうことがあります。 その場合はエラーになり、先に進めません。

確実に切り替える方法

  1. 1. 認証画面が出たら、表示されているアカウントのメールアドレスを必ず確認する
  2. 2. 会社のアカウントだったら「別のアカウントを使用」を選び、個人の @gmail.com に切り替える
  3. 3. アカウント選択画面が出ない場合は、認証用URLをコピーして シークレットウィンドウ（プライベートウィンドウ）に貼り付けて開く

間違ったアカウントでログインしてしまった場合:
CLI内で /logout を実行してから、 もう一度 agy を起動してやり直してください。

📊 無料枠はどのくらい？

Googleは無料枠の正確なリクエスト数を公開していません。公式ドキュメントでは 「Google AI Pro／Ultra 以外のユーザーには、週次で回復する相応のクォータが割り当てられる」 とだけ書かれています。

プラン別のクォータ（公式）

  • • 無料（その他のユーザー） - 相応のクォータ。週次で回復
  • • Google AI Pro - 潤沢なクォータ。5時間ごとに回復（週次上限に達するまで）
  • • Google AI Ultra - 最大のクォータ。5時間ごとに回復＋週次上限が最も高い。サードパーティモデルも利用可

※ 全プランで Gemini モデルとCLIを含む全機能が使えます。Tab補完は全プラン無制限。

実際の目安（非公式・コミュニティ報告）

  • • Gemini Flash で 1日あたり約20リクエスト、5時間ごとのローリング回復
  • • モデルごとに別々のクォータ枠（Flashを使い切ってもPro側は残る）
  • • 週次上限に達すると、リセットまで最大7日間ロックされることがある

※ 2026年4月時点の第三者調査による数値です。提供開始時（2025年11月）は約250リクエスト/日でしたが大幅に縮小されました。 公式の数値ではないため、今後も変動する可能性があります。

⚠️ 消費が想像より早い点に注意
Antigravity のクォータはトークン数ではなく「エージェントがこなした作業量」で計算されます。 1回の指示で裏側の複数エージェントが動くため、体感より早く消費します。 研修中は Gemini 3.6 Flash を使うことをおすすめします（下記参照）。

残量はCLI内で /usage（別名 /quota）を実行すると、モデルごとに確認できます。

🎯 どのモデルを使えばいい？

研修では Gemini 3.6 Flash をおすすめします。 2026年7月21日にリリースされた新しいモデルで、 ひとつ前の 3.5 Flash より出力トークンを17%削減できます。 マルチステップの作業でも推論ステップとツール呼び出しが少なく済むため、 無料枠の消費を抑えられます。

Antigravity で使える主なモデル

  • • Gemini 3.6 Flash - 高速。コード生成向けのバランス型。研修ではこれ
  • • Gemini 3.5 Flash - ひとつ前の高速モデル
  • • Gemini 3.1 Pro - 複雑な推論向け。応答は遅め、消費も大きい

※ Flash系には Low / Medium / High の強度指定があります。迷ったら既定のままで構いません。
※ 利用できるモデルはプランによって異なります。一覧に出ていない場合は Gemini 3.5 Flash を選んでください。

💡 「Flash-Lite」を探さないでください

より軽い Gemini 3.5 Flash-Lite というモデルも存在しますが、これは大量データの処理・抽出向けで、 Antigravity では提供されていません。 コーディング用途では 3.6 Flash のほうが適しています。

公式サイト・ドキュメント

https://antigravity.google/ https://antigravity.google/docs/cli/install（インストール手順）

⚠️ 必ず WSL2（Ubuntu）内にインストールしてください

Laravelのプロジェクトは WSL2 側に置くため、AIにコードを読ませるには CLIも WSL2 側にある必要があります。

公式には Windows（PowerShell）用のインストーラー irm https://antigravity.google/cli/install.ps1 | iex もありますが、本研修では使いません。 Windows側に入れるとWSL2内のファイルを扱いづらくなります。

インストールコマンド

WSL2（Ubuntu）内で実行:

curl -fsSL https://antigravity.google/cli/install.sh | bash

Node.js や Python のランタイムは不要で、単体の実行ファイルとして ~/.local/bin/agy に配置されます。 コマンド名は agy です。

⚠️ PATHが通っていない場合: ~/.local/bin がPATHに含まれていないと、 インストーラーが「シェル設定ファイルに追記する1行」を表示します。その行を ~/.bashrc に追記し、 source ~/.bashrc を実行してください。

インストール確認

agy --version

バージョンが表示されれば成功です。
※ agy version（ハイフンなし）は対話モードで動くため、 確認には agy --version を使ってください。

初回セットアップ

agy
  1. 1. OSのキーチェーンに保存済みの認証情報があれば、自動でログインされます
  2. 2. 初回はブラウザが自動で開くので、個人のGoogleアカウントでログイン
  3. 3. 「許可」をクリックするとターミナルに戻り、プロンプトが表示されれば成功

※ WSL2からブラウザが自動で開かない場合は、認証用URLが表示されるので、 Windows側のブラウザで開いて、表示されたコードをターミナルに貼り付けます。
※ ログアウトしたいときは、CLI内で /logout を実行します。

よく使うコマンド

ターミナルで実行するコマンド

  • • agy - CLIを起動
  • • agy --version - バージョン確認
  • • agy update - 最新版に更新
  • • agy changelog - 更新履歴を表示
  • • agy help - ヘルプを表示

CLI起動中に使うスラッシュコマンド

  • • /usage（/quota） - モデルごとのクォータ残量を確認
  • • /credits - AIクレジットの使用状況を確認
  • • /diff - 変更差分を表示
  • • /codesearch - コードベースを検索
  • • /agents - エージェントの管理
  • • /permissions - 権限設定
  • • /resume - 前回のセッションを再開
  • • /logout - ログアウト

ファイル指定方法 (`@`マーク)

プロンプト内で `@` に続けてファイルパスを入力すると、そのファイルをコンテキストとして Antigravity CLI に渡すことができます。これにより、ファイルの内容に基づいた質問や指示が可能になります。

単一ファイルの例:

@routes/web.php このファイルを解説して

複数ファイルの例:

@app/Models/User.php @app/Http/Controllers/UserController.php リレーション確認

トラブル1: WSL 2エラー

エラー: "WSL 2 installation is incomplete"

解決策:

  1. 1. PowerShellを管理者権限で開く
  2. 2. 以下のコマンドを実行:
wsl --install
wsl --set-default-version 2

3. PCを再起動してDocker Desktopを再度起動

トラブル2: ポート番号被り

エラー: "address already in use"

解決策: docker-compose.ymlのポート番号左側を変更します。

ports:
  - 8080:80    # Webサーバー
  - 3307:3306  # MySQL

アクセスURL: http://localhost:8080

トラブル3: Docker未起動

エラー: "Cannot connect to the Docker daemon"

解決策: スタートメニューからDocker Desktopを起動します。タスクバーにDockerアイコンが表示されていることを確認してください。

トラブル4: .env設定誤り

エラー: "SQLSTATE[HY000]"

解決策: src/.envの設定値をdocker-compose.ymlと一致させて再起動します。

docker compose down -v
docker compose up -d

トラブル5: ボリュームの問題

症状: 古い設定が残っている

解決策: -vオプション付きで削除します。

docker compose down -v
docker compose up -d
docker compose exec app bash
php artisan migrate

⚠️ 警告: 本番環境では-vオプションは使用禁止です！

トラブル6: VSCodeがWSLに接続できない

症状: 「WSL: Ubuntu」と表示されない

解決策:

  1. 1. WSL拡張機能が正しくインストールされているか確認
  2. 2. VSCodeを再起動
  3. 3. WSL2（Ubuntu）を再起動
  4. 4. それでもダメなら、VSCodeの設定から「Remote.WSL: Ubuntu」を検索して有効化

よく使うDockerコマンド集

docker compose up -d

コンテナ起動

docker compose down

コンテナ停止

docker compose down -v

コンテナ停止＋ボリューム削除

docker compose exec app bash

appコンテナに入る

docker compose ps

docker compose logs

exit
