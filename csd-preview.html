🧪 実践的なTDD

🧪

DBを使ったテスト

TDDはハードコーディングされた単体テストだけで終わらせません。

💡 なぜDBを使ったテストが重要なのか？

現場のバグの多くはデータベースとの連携部分で発生します。
モックだけのテストでは、本番環境で起きる問題を検出できません。

✅ ORMでDBにデータを保存

正常に完了したか、しなかったかのテスト

保存した値・件数を DB 用のアサーションで検証

✅ DBからデータを取得

取得できたかどうかのテスト

条件どおりのデータだけが取れるか（完了済みだけ、など）を検証

✅ テストごとにDBをリセット

テストの独立性を保証

テスト用のDB（SQLite）を毎回まっさらな状態から作り直して実行

🔄 CI/CD パイプライン

💡 なぜCI/CDが必須スキルなのか？

手動デプロイはヒューマンエラーの温床です。
現代の開発チームでは、CI/CDパイプラインの構築・運用は当たり前のスキルとして求められています。

⚙️

CI（継続的インテグレーション）

GitHubへのpushにより：

  • ✓ 自動テスト実行（GitHub Actions）
  • ✓ 静的解析（Larastan）とコード整形チェック（Pint）
  • ✓ テストが通らないとマージできないブランチ保護

問題を早期発見し、統合リスクを最小化

🚀

CD（継続的デリバリー）

実際に体験：

  • ✓ AWS EC2 へ自動デプロイ
  • ✓ 本番環境での確認

コードをpushするだけで本番反映を実現
