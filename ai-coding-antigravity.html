★ いちばん重要な知識

講師がいちばん伝えたいこと：ハーネス

講義の中では、あくまで Antigravity CLI というハーネスの使い方を説明しています。
でも、本当に伝えたいのはこれです。これが、いちばん重要な知識です。

🎬 解説動画「ハーネスってなに？」（約3分半・音声あり）

① LLM は「文字を受け取って、文字を返す」だけ

AI の中心にある LLM だけでは、ファイルを開くことも、コマンドを実行することもできません。

② ハーネスが、LLM を「作業できる AI」にする

馬具が馬の力を馬車を引く力に変えるように、ハーネスは LLM に道具（ファイル・コマンド・Web）を渡し、くり返し（考える → 動く → 結果を見る）、文脈（AGENTS.md・スキル）、安全（許可・権限）を足します。

③ 同じモデルでも、ハーネスで差が出る

GitHub Copilot では Claude・GPT・Gemini のモデルを選べます。同じモデルでも、ブラウザのチャットと、ターミナルで動く CLI のハーネスでは、できることがまったく違います。CLI は自分のパソコンの上で、ファイル・コマンド・Linux の権限まで使えます。

④ ハーネスを「作る」仕事も増えている

文字しか返せない LLM を、お客さまにとって使いやすい形で、執事のように働かせる。Web 開発の現場でも、そんなハーネスを作る案件が増えています。

だから、ハーネスの仕組みを理解して、使い方に慣れること。

ツールの名前やモデルは、これからもどんどん変わります。でも「LLM ＋ ハーネス」という仕組みを知っていれば、どのツールでも使いこなせて、自分で作る側にも回れます。

💡 この動画も、ハーネスを使って作りました。 AI に台本を書かせ、Gemini の音声合成で3人の声を作り、ブラウザで画面を描いて、動画に組み立てるところまで。 ブラウザのチャットではできない作業も、CLI のハーネスならできる、という実例です。

なぜ Antigravity CLI なのか

📢 Gemini CLI は提供を終了しました

これまで本講座で使ってきた Gemini CLI は、 2026年6月18日 に 無料ユーザー・Google AI Pro／Ultra ユーザー向けの提供を終了しました。

後継として Google が公式に案内しているのが、本ページで学ぶ Antigravity CLI です。
（※ Standard／Enterprise ライセンスをもつ企業ユーザーは、引き続き Gemini CLI のサポートを受けられます）

🕒 これまでの流れ

2025年11月18日：Gemini 3 と Google Antigravity を発表

Google が新モデル Gemini 3 と、それを土台にした エージェント型開発プラットフォーム Google Antigravity（IDE）を同時公開。 AIを「ツール」ではなく「能動的な開発パートナー」として位置づけ直しました。

2026年5月19日：Antigravity CLI を一般公開

Antigravity プラットフォームの一部として、ターミナル版の Antigravity CLI をリリース。あわせて Antigravity 2.0（デスクトップアプリ・CLI・SDK）が登場しました。

2026年6月18日：Gemini CLI（無料／Pro／Ultra）が提供終了

開発リソースを後継製品に集約するため、Gemini CLI の一般向け提供を終了。 以降は Antigravity CLI に一本化されました。

2026年9月：Gemini 3.8 Flash が登場

Antigravity CLI の標準モデルが Gemini 3.8 Flash になりました。 無料プランでも使えます（使える量には上限があります）。

2026年10月時点：agy 1.3 系

ほぼ毎週アップデートされています。/plan（計画モード）、 /diff（変更の確認）、/effort（考える深さの調整）、 プラグイン管理（/plugin）、Gemini APIキーでの利用などが加わりました。

💡 移行の理由

Google の公式アナウンスでは、移行の背景がこう説明されています。

  • ① 開発のスタイルが「マルチエージェント」へ進化した
    2025年初頭の「AIに1つずつ質問する」使い方から、 複数のエージェントが互いに連携し、作業を分担して複雑な問題を解く使い方へとニーズが変化しました。
  • ② 製品を1つに集約して品質を高めるため
    複数のツールに力を分散させるのではなく、 マルチエージェント時代に合わせた単一の製品に開発リソースを集中することにしました。
  • ③ Gemini CLI の資産はそのまま引き継げる
    Skills・Hooks・Subagents・Extensions（Antigravity では「プラグイン」）といった 主要機能が Antigravity CLI に継承されています。GEMINI.md もそのまま読み込まれます。

出典： Google Developers Blog「Transitioning Gemini CLI to Antigravity CLI」、 Antigravity CLI 公式ドキュメント（Installation & auth）、 Plans and AI credits、 Codelab: Hands-on with Antigravity CLI、 agy 1.3.3 の agy changelog

Antigravity CLIとは？

🚀 概要

Antigravity CLI は、Googleが提供する
ターミナルから直接AIエージェントを動かせるコマンドラインツールです。

エージェント型開発プラットフォーム「Google Antigravity」のターミナル版にあたり、 裏側では Gemini 3.8 Flash などの Gemini モデルが動いています。 コマンド名は agy です。

✨ 主な特徴

  • • 単体で動くプログラム：Node.js / npm は不要。インストーラ1行で導入できます
  • • マルチエージェント：複数のサブエージェントを並列に動かしてタスクを分担
  • • ファイル操作・コマンド実行：許可を取りながらコードの読み書きやコマンド実行を代行
  • • 計画モード（/plan）：いきなり作らず、まず計画を出させてから承認できる
  • • 2通りの使い方：Google アカウントでログイン、または Gemini APIキーで利用
  • • 資産の継承：Gemini CLI の Skills / Hooks / Subagents / 拡張（プラグイン）に対応

💳 料金プランと使える量

無料の Google アカウントでも、CLI を含むすべての機能と Gemini 3.8 Flash／Gemini 3.1 Pro が使えます。 違うのは使える量です。

プラン 使える量（クォータ）
無料（Pro／Ultra 以外） 一定量が1週間ごとに回復。週の上限あり
Google AI Pro 多めの量が5時間ごとに回復（週の上限まで）。足りない分は AI クレジットで追加可能
Google AI Ultra 最も多い量が5時間ごとに回復。他社モデルも利用可能
Gemini APIキー 上の枠とは別。キーの持ち主の Google AI Studio の上限・料金で動きます

※ 具体的な回数は公開されておらず、Google 側の空き状況や作業の重さによって変わります（上限は予告なく変更されることがあります）。

⚠️ 無料枠を使うときの注意

Antigravity CLI は複数のサブエージェントを並列で起動できるため、 1つの指示が裏で複数のワーカーを動かし、無料枠の消費が想像より早くなることがあります。
残りの量は /usage コマンドで確認できます。 無料枠は週単位で回復するので、講義の前に使い切らないよう注意してください。

✅ 前提条件

ターミナルが使えること（Mac はターミナル.app、Windows は環境構築で用意した WSL2 の Ubuntu）。
次のどちらかを用意してください。

  • • 個人の Google アカウント（基本はこちら）
  • • Gemini APIキー（会社の制限でログインできない人、無料枠を使い切った人など。講師から借りられます）

ハンズオン：Antigravity CLIを使ってみよう

インストールから基本操作までを体験します

0

インストール

公式インストーラを実行します。環境を自動判別し、agy を配置します。

あなたのPC：

🍎 macOS / Linux:

curl -fsSL https://antigravity.google/cli/install.sh | bash

~/.local/bin/agy にインストールされます。

🪟 Windows（WSL2 の Ubuntu）:

環境構築で用意した WSL2 の Ubuntu ターミナルで実行します（PowerShell ではありません）。

curl -fsSL https://antigravity.google/cli/install.sh | bash

Ubuntu の中の ~/.local/bin/agy にインストールされます。 公式には PowerShell 用のインストーラーもありますが、この講座では使いません。

✅ インストール確認:

ターミナルを一度閉じて開き直してから実行してください（PATH の設定を反映させるため）。

agy --version

1.3.3 のようにバージョンが表示されれば成功です（2026年10月時点は 1.3 系）。
すでにインストール済みの人は agy update で最新版にしておきましょう。

1

初回起動と Google ログイン

作業用のフォルダに移動してから、Antigravity CLI を起動します。

あなたのPC：

📝 実行するコマンド:

mkdir -p ~/agy-handson && cd ~/agy-handson
agy
# Ubuntu（WSL2）のターミナルで
mkdir -p ~/agy-handson && cd ~/agy-handson
agy

🎨 初回起動時の流れ:

1. ログイン方法の選択

次の画面が出ます。「1. Google OAuth」を選んで Enter。

Welcome to the Antigravity CLI. You are currently not signed in.

Select login method:
> 1. Google OAuth
  2. Use a Google Cloud project

※「2. Use a Google Cloud project」は会社の GCP（Vertex AI）を使う人向けです。この講座では使いません。

2. ブラウザでログイン

ブラウザが開くので、Google アカウントでログインします。
ブラウザに認証コードが表示された場合は、それをコピーしてターミナルに貼り付けて Enter。
（SSH などリモート接続中は、表示された URL を手元のブラウザで開きます）

3. 初期設定

色テーマを選び、利用規約に同意します。

4. フォルダの信頼（Trust）

「このフォルダを信頼しますか？」と聞かれます。信頼すると、AIがこのフォルダ内のファイルを読み書き・実行できるようになります。 自分の作業フォルダであれば信頼を選びましょう。

✅ 成功のサイン:

入力欄（プロンプト）が表示されれば成功です。
ログイン情報はOSのキーチェーンに保存され、次回からは自動でログインされます。

💡 ログイン画面に「APIキー」の選択肢はありません

APIキーで使いたい人は、この画面では何も選ばずに Ctrl+C で抜けて、 次の「手順2：APIキーで使う」に進んでください。 正しく設定すれば、この画面は出なくなります。

2

APIキーで使う（必要な人だけ）

Google ログインができない人・無料枠を使い切った人は、Gemini APIキーで使えます。
この講義では講師が APIキーを貸し出します。必要な人は声をかけてください。

❗ 設定は「2つセット」です（片方だけでは動きません）

① 設定ファイル

settings.json に "modelProvider": "gemini" を書く

② 環境変数

GEMINI_API_KEY にキーを入れる

※ 環境変数だけ入れても Google ログイン画面が出ます。
※ 変数名は GEMINI_API_KEY だけが有効です（GOOGLE_API_KEY や .env ファイルは読まれません）。

あなたのPC：

🍎 macOS / Linux の手順

① 設定ファイルを開く

ファイルの場所：~/.gemini/antigravity-cli/settings.json（一度 agy を起動すると作られます）

open -e ~/.gemini/antigravity-cli/settings.json

"modelProvider": "gemini" の1行を追加します。 前の行の最後にカンマ（,）を付けるのを忘れずに。 

{
  "model": "Gemini 3.8 Flash (Medium)",
  "trustedWorkspaces": [ ... ],
  "modelProvider": "gemini"
}

② キーを環境変数に入れて起動

export GEMINI_API_KEY="講師から受け取ったキー"
agy

export はそのターミナル（タブ）の中だけで有効です。 agy を起動するのと同じタブで実行してください。
うまく入ったかは echo $GEMINI_API_KEY で確認できます。

🪟 Windows（WSL2 の Ubuntu）の手順

環境構築で用意した WSL2 の Ubuntu ターミナルで実行します（PowerShell ではありません）。

① 設定ファイルを開く

ファイルの場所：Ubuntu の中の ~/.gemini/antigravity-cli/settings.json（一度 agy を起動すると作られます）

code ~/.gemini/antigravity-cli/settings.json

"modelProvider": "gemini" の1行を追加して保存します（前の行の最後にカンマ（,）を付ける）。

② キーを環境変数に入れて起動

export GEMINI_API_KEY="講師から受け取ったキー"
agy

agy を起動するのと同じ Ubuntu のターミナルで実行してください。 うまく入ったかは echo $GEMINI_API_KEY で確認できます。

✅ 成功のサイン:

  • • ログイン方法の選択画面が出ずに、そのまま入力欄が表示される
  • • 起動時のバナーや /help に Gemini API key と表示される

🔐 借りたキーの取り扱い（必ず守ってください）

  • • キーをスクリーンショット・チャット・Slack・GitHub に載せない。画面共有中に echo $GEMINI_API_KEY を実行しないよう注意
  • • キーをプロジェクトのファイルに書かない（Git にコミットされる危険があります）
  • • ~/.zshrc などに書いて保存するのは自分のキーのときだけ。借りたキーは毎回 export で入れます
  • • 同じキーを受講者全員で使うため、同時に大量のリクエストを送ると全員が一時的に止まることがあります（1分ほど待つと回復します）
  • • 講義が終わるとキーは削除されます。その後は下の「元に戻す」を行ってください

↩️ 講義のあと：Google ログインに戻す

  1. settings.json から "modelProvider": "gemini" の行を消す（前の行の最後のカンマも消す）
  2. ターミナルを開き直して agy を起動 → ログイン画面で「1. Google OAuth」

※ APIキーで使っている間は /logout は効きません（キーは環境変数から読まれているため）。

🔑 自分のキーを作りたい人は

Google AI Studio（aistudio.google.com/apikey） で無料で作れます。無料枠には1日・1分あたりの上限があり、無料枠で送った内容は Google の製品改善に使われることがあります。 会社のソースコードを扱うときは、会社のルールを確認してください。

モデルの選び方

使うモデルは /model で切り替えられます。 

❯ /model
おすすめ

Gemini 3.8 Flash

最新・標準モデル。速くて賢い。この研修ではこちらを使用

参考

Gemini 3.1 Pro

難しい設計・推論向け。応答は遅めで、使える量の消費も多め

参考

Gemini 3.7 / 3.6 / 3.5 Flash

ひとつ前の世代。特に理由がなければ 3.8 Flash を選べばOK

💡 High / Medium / Low とは？（/effort）

モデル名の後ろの (High) (Medium) (Low) は「どれだけ深く考えるか」です。 High ほど丁寧ですが遅く、使える量の消費も増えます。迷ったら Medium。 /effort でいつでも変えられます。 

❯ /effort medium
4

日本語設定（AGENTS.md）

英語で応答されることがあります。
ルールファイルを作って、常に日本語で応答させましょう。

📖 ルールファイルとは？

Antigravity CLI が起動時に自動で読み込む指示ファイルです。
AIへの指示を書いておくと、毎回のやり取りに自動で適用されます。

📁 置き場所:

プロジェクト用：AGENTS.md（推奨）

プロジェクトのフォルダ直下に置きます。そのプロジェクトだけに効きます。
旧 Gemini CLI の GEMINI.md もそのまま読み込まれます。

全プロジェクト共通：~/.gemini/GEMINI.md

どのフォルダで起動しても効きます（~/.gemini/AGENTS.md でも可）。

ルールを分けたいとき：.agents/rules/*.md

ルールが増えてきたら、テーマごとにファイルを分けて置けます。

※ 旧版のこのページで紹介していた .antigravity.md は読み込まれません。AGENTS.md に名前を変えてください。

📝 設定例:

プロジェクトのフォルダ直下に AGENTS.md を作り、以下を書きます：

Always respond in Japanese.

AIに「AGENTS.md を作って、常に日本語で応答するルールを書いて」と頼んでも作ってくれます。 書いたあとは agy を起動し直すと確実に反映されます。

💡 プロジェクト固有の設定例

ルールファイルには、そのプロジェクト特有の情報を書いておくと便利です：

  • • プロジェクトの概要・目的
  • • 使用している技術スタック
  • • コーディング規約・命名規則
  • • よく使うコマンド（例：artisan は docker compose exec app の中で実行する）
5

基本的な使い方

対話モードで頼んでみましょう。自然な日本語で入力できます。

📝 試してみよう（対話モード）:

❯ JSとHTMLとCSSでTodoアプリのUIを作って

✅ 期待される動き:

AIがHTML、CSS、JavaScriptのファイルを作ってくれます。
ファイルを作ったりコマンドを実行したりする前に「許可しますか？」と聞かれるので、内容を見て許可してください。

続けて「タスクの削除機能を追加して」など、 会話を続けることで機能を追加していけます。

🗺️ 計画モード（/plan）：大きめの作業はまず計画から

頼みごとの前に /plan を付けると、AIはすぐに作らず、まず作業計画を出します。 計画を読んで、良ければ承認、直したければコメントします。チームで作業するときに特におすすめです。 Shift+Tab でもモードを切り替えられます。 

❯ /plan Laravelで掲示板アプリを作りたい

⚡ ワンショット実行（非対話モード）:

-p オプションで、対話画面を開かずに1回だけ指示を渡せます。

agy -p "このリポジトリの構成を説明して"

💡 その他の頼み方の例:

  • • 「このディレクトリの構造を教えて」
  • • 「Laravelでユーザー認証機能を作って」
  • • 「このエラーの原因を教えて」（エラー文をそのまま貼る）

📎 ファイル参照（@記法）

@ を入力するとファイル名の候補が出て、そのファイルをAIに渡せます。 

❯ @main.py このコードを説明して

コードの説明

@app.py 何をしている？

バグの発見

@calculator.py バグがないかチェックして

リファクタリング

@utils.js もっと良い書き方を教えて

🧭 よく使うスラッシュコマンド

/helpヘルプ・コマンド一覧・ショートカット
/model ／ /effortモデル・考える深さの切り替え

/config設定（色テーマ・ツール実行の許可レベルなど）
/logoutGoogle ログインの解除（APIキー利用中は無効）
/exit終了（Ctrl+D を2回でも終了）
?

困ったときは

❓ command not found: agy と出る

ターミナルを閉じて開き直してください。それでもだめなら、インストールコマンドをもう一度実行します。

❓ APIキーを入れたのに、ログイン方法の選択画面が出る

settings.json に "modelProvider": "gemini" が入っていません。手順2の①を確認してください。

❓ modelProvider is set to "gemini" ... but the GEMINI_API_KEY environment variable is not set

キーが入っていないタブで起動しています。そのタブで export GEMINI_API_KEY="..." をしてから agy。
キーを使い終わった人は、settings.json から modelProvider の行を消せば Google ログインに戻ります。

❓ API key not valid と出る

キーのコピーミス（前後の空白・引用符の付け忘れ）か、キーがすでに削除されています。講師に確認してください。

❓ 使用量の上限に達した（quota / rate limit）

/usage で回復時刻を確認します。急ぐときは講師からAPIキーを借りて手順2で続けられます。

❓ 英語で返事が来る

手順4の AGENTS.md を作り、agy を起動し直してください。

❓ AIが関係ないファイルまで変えてしまった

/diff で変更を確認し、/rewind で前の時点に戻せます。

Laravelでアプリを作る前に

データベース連携アプリを作るための基礎知識を確認しましょう

⚠️ 重要：Laravelコマンドの実行場所

Laravelの php artisan コマンドは、Dockerコンテナの中で実行します。 

# まずコンテナに入る
docker compose exec app bash

# コンテナ内でartisanコマンドを実行
php artisan make:model Todo -m

※ コンテナから出るときは exit を入力

🏗️ MVCアーキテクチャとは？

LaravelはMVC（Model-View-Controller）というパターンでコードを整理します。
役割ごとにファイルを分けることで、コードが整理され保守しやすくなります。

📦 Model

データの管理

  • • DBのテーブルと対応
  • • データの取得・保存
  • • ビジネスロジック
app/Models/Todo.php

🎨 View

画面の表示

  • • HTMLの生成
  • • ユーザーへの表示
  • • Bladeテンプレート
resources/views/todo.blade.php

🎮 Controller

処理の制御

  • • リクエストの受付
  • • Modelを呼び出す
  • • Viewを返す
app/Http/Controllers/TodoController.php

🔄 処理の流れ

ユーザー → Controller → Model → DB → Model → Controller → View → ユーザー

🗄️ LaravelでDBを作る流れ

1

Model と Migration を作成

1つのコマンドでModelとテーブル定義を同時に作れます

php artisan make:model Todo -m

-m オプションで migration（テーブル定義）も一緒に作成

2

Migration ファイルを編集

テーブルのカラム（列）を定義します

// database/migrations/xxxx_create_todos_table.php
public function up()
{
    Schema::create('todos', function (Blueprint $table) {
        $table->id();
        $table->string('title');        // タイトル
        $table->boolean('completed')->default(false); // 完了フラグ
        $table->timestamps();        // 作成日時・更新日時
    });
}
3

Migration を実行

定義したテーブルを実際にDBに作成します

php artisan migrate
4

Controller を作成

CRUD操作を行うControllerを作成します

php artisan make:controller TodoController --resource

--resource オプションでCRUD用のメソッドが自動生成されます

💡 AIに任せよう！

これらの手順はAIが全てやってくれます。
「TodoアプリをLaravelで作って」と伝えれば、Model・Migration・Controllerを自動で作成・編集してくれます。
